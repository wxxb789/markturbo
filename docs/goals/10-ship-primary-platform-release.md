# Goal 10 — Ship a primary-platform public-quality release

## Objective

Produce one publicly installable Windows 11 x64 release that installs and
launches without a terminal, includes every required font and conditional worker
artifact, preserves user files and supported state across every upgrade path the
release explicitly claims, removes only application-owned files on uninstall,
passes the full release suite and a clean-machine end-to-end smoke, and presents
a user-first download, privacy explanation, screenshot set, and short Review
demonstration; do not claim support, signing, migration, or update behavior that
was not exercised.

## Product contract alignment

**Disposition:** Retained and revised on 2026-08-29.

Windows 11 x64 is the only public-quality platform for this release. Windows
10 x64, macOS, and Linux may remain compatibility-only but must not be described
as public-quality without their own clean-machine evidence. Release acceptance
requires the integrated Goal 07 and Goal 08 workflow: a Review can include
explicitly user-selected, disclosed Effective Agent Context and apply only the
user-approved revision.

## Release boundary

This goal packages and proves the product completed by all preceding applicable
goals, including conditional Goal 05 and security Goal 05A. It is not a
feature-development milestone.

## In scope

- One conventional Windows 11 x64 installable artifact, plus checksums and all
  required notices.
- Application identity, icon, file layout, math fonts, sample workspace, and the
  model worker when Goal 05 took the go path.
- Code signing and notarization where the platform and available credentials make
  them part of a credible public installation. Never label an unsigned artifact
  as signed.
- Install, launch, upgrade, move/repair where supported, and uninstall behavior.
- Preserve ordinary user documents, settings, recent paths, and recovery data
  according to the policies established earlier; uninstall may offer an explicit
  separate data-removal choice but must not silently remove user content.
- Verify launch from the desktop shell, a direct file/folder argument, the
  welcome state, bundled sample, New/Paste, Save As, native preview, graceful
  close, and the integrated Goal 07/08 Review workflow.
- Verify the worker-missing diagnostic when Goal 05 applies, without leaving the
  core application unusable.
- A user-first README/release page whose first path is Download → Install → First
  Review, not Build from source.
- Current screenshots generated by Goal 09 and a short recording that shows a
  rough artifact, clarification, proposed diff, and user approval without
  exposing API keys or private content.
- A concise privacy section naming what stays local, where credentials and
  recovery data live, and how a local endpoint differs from a hosted one. Before
  a request it must show local/remote status, provider wire format, normalized
  endpoint identity, selection/document/document-plus-named-context scope, and
  that protocol framing and the listed source content leave the device. An Agent
  Skill package disclosure must list every included file's normalized relative
  path, byte size, and inclusion reason; an unlisted file must not leave the
  device and an omitted normally in-scope supporting file makes the result
  partial.
- CI/release automation that builds the same artifact used in acceptance and
  fails on missing fonts, helper binaries, licenses, signatures required by the
  chosen channel, or version disagreement.

## Out of scope

- Adding application features, changing Review prompts, redesigning UI, or
  broadening Effective Context semantics.
- Claiming public-quality support for Windows 10 x64, macOS, or Linux without a
  separately approved contract and clean-machine evidence.
- Accounts, cloud sync, analytics, paid licensing, an auto-updater,
  package-manager publication, or a website.
- Hiding platform warnings, bypassing signing requirements, or weakening tests to
  make a release artifact pass.
- Publishing evaluation artifacts containing private or licensed content that
  cannot be redistributed.

## Clean-machine acceptance

On a clean Windows 11 x64 machine or equivalent clean Windows 11 x64 VM:

1. Download and verify the published checksum.
2. Install through the documented user path without developer tools.
3. Launch from the desktop shell and reach the welcome state.
4. Open the bundled sample with working native Markdown and compatibility smoke
   coverage for Mermaid, D2, and math; these renderers are not the release thesis.
5. Create/paste a Unicode prompt, save it as ordinary Markdown, close, and reopen
   it byte-correctly.
6. Configure a controlled test endpoint through Goal 05A's supported credential
   path, without developer tools and without exposing the key in settings, logs,
   process arguments, screenshots, or recovery data.
7. Complete Review for at least one checked-in artifact from every first lens:
   task prompt, specification or plan, agent instructions, and Agent Skill. The
   Agent Skill case includes at least one supporting file and proves by request
   inspection that the normalized relative path, byte size, and inclusion reason
   disclosed for each file exactly match the transmitted files.
8. Resolve the shipped `codex-agents-md-2026-08-29` Effective Agent Context
   profile, explicitly select named context sources for Review, and verify the
   outbound disclosure identifies the endpoint plus document and selected-context
   scope. Treat any other discovered instruction file as inventory-only.
9. Complete that integrated Review and one accepted/rejected mixed-hunk revision;
   verify that only the explicitly approved result applies.
10. Exercise every upgrade path the release claims. If this is the first supported
   installer release, say so and test a staged upgrade between two release
   candidates instead of inventing compatibility with an older archive.
11. Uninstall and prove that user-created Markdown remains intact and no product
    process remains running.

## Completion evidence

- The exact published artifact hash is the one accepted on the clean machine.
- Release automation and packaging tests pass from a clean checkout.
- `cargo fmt --all -- --check` passes.
- `cargo clippy --workspace --all-targets` introduces no new warnings.
- `cargo test --release --workspace` passes and the pass count is published in
  the release evidence.
- The Goal 04 platform-appropriate startup, memory, CPU, and window harnesses
  pass against the published executable; run and pass
  `uv run --project scripts scripts/mt.py probe -- ...` against the Windows 11
  x64 artifact.
- The measured startup result does not regress beyond the guardrail approved in
  Goal 04, or the release is blocked with the regression documented.
- The download page names the one verified platform and accurately labels all
  other builds as experimental or unavailable.
- The project owner approves the final artifact, screenshots, demonstration, and
  release copy.

## Stop and ask

Stop before publication if signing credentials required by the chosen release
channel are unavailable, the clean-machine smoke cannot be completed, upgrade or
uninstall can remove user content, privacy copy disagrees with actual transport,
or the packaged binary differs from the tested artifact. Do not publish a draft
as a public-quality release to satisfy the order.

## Boundary for the next goal

This goal completes product delivery, not evidence of recurring value. Goal 11
owns post-release validation. New platform ports, additional harness semantics,
optional renderer processes, downstream prompt execution, and commercial
features remain out of scope until that evidence supports a new goal.
